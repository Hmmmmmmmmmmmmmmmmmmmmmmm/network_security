GH
GitHub Clone
Clone, install, configure, run — full control
▾
01
Clone the repository
Download the project to your machine.
git clone https://github.com/Hmmmmmmmmmmmmmmmmmmmmmmm/network_security.git
cd network-security-ml
02
Install the dependencies
Everything the project needs in one command.
pip install -r requirements.txt
03
Create a .env file with your credentials
The pipeline pulls data from MongoDB Atlas and logs experiments to DagShub — you'll need free accounts for both. Create a file called .env in the project root:
# .env — fill in your own values
MONGO_DB_URL=mongodb+srv://your-user:your-password@cluster.mongodb.net/
DAGSHUB_REPO_OWNER=your-dagshub-username
DAGSHUB_REPO_NAME=network_security
MongoDB Atlas has a free tier (M0) that's more than enough. DagShub is free for public repos and handles all the experiment tracking automatically.
04
Start the app
One command and you're live at localhost:8000. Training will work in full.
python app.py
DK
Docker
Pull a ready-to-run image — no install needed
▾
01
Pull the image
The image already has the trained model bundled in — predictions work the moment it starts.
docker pull hmmmmmmmmm/netguard-ml:latest
02
Create a .env file
Same credentials as the GitHub path — MongoDB Atlas and DagShub. Only needed if you plan to run training; predictions skip these entirely.
# .env
MONGO_DB_URL=mongodb+srv://your-user:your-password@cluster.mongodb.net/
DAGSHUB_REPO_OWNER=your-dagshub-username
DAGSHUB_REPO_NAME=network_security
03
Run it
Opens at localhost:8000. Training is enabled by default — only this Render deployment has it switched off.
docker run --env-file .env -p 8000:8000 \
  hmmmmmmmmm/netguard-ml:latest
TRAINING_DISABLED is only set on this Render deployment and is not present in the Docker image — so training works out of the box locally.
